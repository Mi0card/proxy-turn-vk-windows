# WinDTT

Windows и macOS GUI-клиент для туннеля [WireGuard over VK TURN](https://github.com/SpaceNeuroX/proxy-turn-vk-android).

Движок (`go_client`, `server_src`) зеркалируется из активного апстрима [SpaceNeuroX/proxy-turn-vk-android](https://github.com/SpaceNeuroX/proxy-turn-vk-android) (исходная кодовая база — amurcanov/proxy-turn-vk-android, ныне архив) и синхронизируется автоматически. GUI — Go + [Wails v2](https://wails.io) + Vanilla JS.

> Образовательный проект. Не предназначен для производственного использования и обхода блокировок.

## Скачать

Готовые сборки — на странице [Releases](../../releases), свежие автоматические сборки — в [Actions](../../actions) (последний успешный запуск → артефакт).

- **Windows** — `WinDTT-v{версия}.exe`, установка не требуется.
- **macOS** — `WinDTT.app` (см. раздел [macOS](#macos) про первый запуск).

## Быстрый старт

1. Вставьте ссылку `wdtt://…` (заполняет форму параметрами подключения) или `qwdtt://config?…` (импортирует готовый профиль с именем и параметрами), либо введите параметры вручную.
2. Нажмите **Подключить**.
3. При необходимости включите **Системный прокси** в шапке или используйте SOCKS5/HTTP напрямую.

Профили подключения сохраняются, переключаются и переименовываются на вкладке **Подключение**.

## Возможности

- Подключение по ссылке (`wdtt://`, `qwdtt://`) или вручную; профили подключения
- SOCKS5 + HTTP прокси с авторизацией через WireGuard userspace (gvisor netstack) — без прав администратора
- **Системный прокси** — перенаправление системного HTTP/HTTPS-трафика (браузеры, Office) через туннель по правилам маршрутизации; Windows (WinINET) и macOS (networksetup)
- **Маршрутизация по правилам** — встроенные правила и группы из geosite/geoip с политиками block / direct / proxy
- **Системный трей** — сворачивание в трей вместо закрытия и при сворачивании окна
- **Автовосстановление соединения** — перезапуск туннеля после выхода из сна и при смене сети
- SSH-деплой `wdtt-server` на VPS с проверкой fingerprint
- Автозагрузка WireGuard-конфига и пинг через туннель в статус-баре; перезапуск при «мёртвом» туннеле (таймаут всех воркеров) с кулдауном
- Светлая / тёмная тема, переключатель аппаратного ускорения (GPU, Windows/WebView2)
- Ручная капча VK решается в нативном окне (Windows — WebView2, macOS — WKWebView через darwinkit; на остальных ОС — заглушка)

## Прокси

### SOCKS5 и HTTP

На вкладке **Прокси** настраиваются SOCKS5- и HTTP-прокси (по умолчанию `127.0.0.1:1080` и `127.0.0.1:1081`), при необходимости — с логином и паролем. Работают через userspace-стек gvisor, права администратора не требуются.

### Системный прокси

Чекбокс **Системный прокси** в шапке приложения. При включении поднимается отдельный HTTP-прокси на случайном порту (`127.0.0.1:<порт>`, без аутентификации) и прописывается в системных настройках: на Windows — WinINET (ветка `HKCU`), на macOS — для всех сетевых сервисов через `networksetup`.

- Подчиняется тем же правилам маршрутизации: по умолчанию трафик идёт через туннель, правила могут направить его напрямую (`direct`) или заблокировать (`block`).
- Для политики по умолчанию (`proxy`) требуется активный туннель — без него запросы отклоняются (502).
- Права администратора не требуются.
- При закрытии или аварийном завершении приложения настройки восстанавливаются автоматически.

Соединения системного прокси видны во вкладке **Логи** → **Подключения**.

## Маршрутизация по правилам

Вкладка **Маршрутизация** направляет трафик по правилам (аналогично приложению Throne). Правила действуют для SOCKS5, HTTP и системного прокси. Каждому правилу задаётся политика:

- **block** — заблокировать соединение (403 / отклонение SOCKS5)
- **direct** — напрямую, в обход туннеля
- **proxy** — через туннель (по умолчанию)

Правила применяются сверху вниз — выигрывает первое совпадение.

### Встроенные правила (без скачивания)

Хранятся в конфиге и работают сразу:

- `domain:<домен>` — точное совпадение (например `domain:example.com`)
- `domain-suffix:<домен>` — домен и все поддомены (`domain-suffix:sobaka.com`)
- `keyword:<текст>` — подстрока в домене (`keyword:youtube`)
- `regex:<шаблон>` — регулярное выражение по домену (`regex:\.example\.com$`)
- `cidr:<подсеть>` — IP-подсеть (`cidr:10.0.0.0/8`)
- `ip:<адрес>` — конкретный IP (`ip:1.2.3.4`)

### Правила из дата-файлов

Правило `ruleset:<тип>-<группа>` ссылается на группу из скачанных дата-файлов:

- `ruleset:geosite-category-ru` — домены группы `CATEGORY-RU` из geosite.dat
- `ruleset:geoip-private` — подсети группы `PRIVATE` из geoip.dat

Группа может быть любой из geosite.dat / geoip.dat. Префикс `ruleset:` можно не писать — он добавляется автоматически (для встроенных правил префикс обязателен).

Дата-файлы скачиваются и кешируются из [runetfreedom/russia-v2ray-rules-dat](https://github.com/runetfreedom/russia-v2ray-rules-dat) кнопкой **Обновить правила**. Парсер работает с бинарным protobuf-форматом (v2fly) без дополнительных зависимостей.

Соединения показываются во вкладке **Логи** → **Подключения** в формате `→ хост:порт - приложение - [время, политика]`, где приложение определяется по процессу-владельцу (Windows/macOS), например `→ 8.8.8.8:2345 - chrome.exe - [10391ms, proxy]`. Если определить не удалось — `—`; заблокированные помечаются `[block]`.

## Настройки

Вкладка **Настройки**:

- **Системный трей** — сворачивать в трей вместо закрытия и при сворачивании окна.
- **Автовосстановление соединения** — перезапускать туннель после выхода из сна и при смене сети.
- **Производительность** — аппаратное ускорение (GPU, Windows/WebView2). Отключение перекладывает отрисовку на CPU; изменение вступает в силу после перезапуска приложения.
- **Импорт / Экспорт** — сохранение всех настроек в JSON-файл и восстановление из него. Импорт полностью заменяет текущую конфигурацию.

## macOS

Готовая сборка (`.app`) — на странице **Releases**.

**Gatekeeper при первом запуске.** Скачанный `.app` помечается атрибутом карантина — macOS покажет «приложение повреждено» или заблокирует запуск. Перед первым запуском одно из двух:

```bash
xattr -cr WinDTT.app
```

либо в Finder: правый клик по `WinDTT.app` → **Открыть** (не двойной клик) → подтвердить в диалоге.

Сборка подписана ad-hoc (без Apple Developer ID) — полноценной нотаризации нет, предупреждение Gatekeeper это не убирает, только описанный выше шаг.

**Системный прокси** работает и на macOS: при включении чекбокса web- и secure-прокси прописываются для всех сетевых сервисов через `/usr/sbin/networksetup` и восстанавливаются при выключении или закрытии приложения. Альтернативно можно прописать SOCKS5/HTTP вручную: System Settings → Network → выбрать сеть → Details → Proxies, либо через терминал:

```bash
networksetup -setsocksfirewallproxy Wi-Fi 127.0.0.1 1080
```

Порты смотрите в UI приложения — они могут отличаться от значений по умолчанию.

## Сборка

Требуется: Go 1.23+, [Wails CLI](https://wails.io/docs/gettingstarted/installation), GCC (MSYS2).

```powershell
# Windows (PowerShell)
.\build.ps1
# Результат: build\bin\WinDTT-v{версия}.exe
```

Или вручную:

```bash
cd go_client && go mod tidy && go build -ldflags="-s -w" -o ../wdtt-client.exe . && cd ..
cd server_src && GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o ../assets/server/wdtt-server . && cd ..
go mod tidy && wails build -ldflags "-s -w"
```

CI собирает автоматически при изменении `AppVersion` в `app.go`.

```
├── proxy.go                ← SOCKS5 + HTTP прокси, WireGuard netstack
├── ruleset_manager.go      ← маршрутизация по правилам (geosite/geoip)
├── system_proxy.go         ← системный прокси: оркестрация и бэкап настроек
├── syscall_windows.go      ← WinINET: реестр + InternetSetOption
├── syscall_darwin.go       ← системный прокси на macOS (networksetup)
├── syscall_unix.go         ← заглушки для кросс-компиляции
├── wake.go                 ← автовосстановление после сна
├── netwatch.go             ← автовосстановление при смене сети
├── tray_windows.go /       ← системный трей (Windows / macOS / заглушка)
│   tray_darwin.go /
│   tray_stub.go
├── captcha_interceptor.go  ← перехват ручной капчи VK
├── captcha_webview_*.go    ← нативное окно капчи (WebView2 / WKWebView)
├── main.go                 ← точка входа, go:embed
├── build.ps1               ← скрипт сборки (Windows)
├── .github/workflows/      ← CI: build.yml, sync.yml
├── tools/icon/             ← генератор иконки
├── go_client/              ← движок (автосинк)
├── server_src/             ← серверная часть (автосинк)
└── frontend/               ← HTML + CSS + JS
```
